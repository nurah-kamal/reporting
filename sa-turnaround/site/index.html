      How this was built

      The two measures

      Working days count the working days after a request was opened, up to and including the day it closed. The calendar measure subtracts the dates and, to be fair to it, stretches each target for weekends (a 3-day target becomes 5 calendar days). The only thing it gets wrong is public holidays.

      The holiday rules

      The library follows the Public Holidays Act 36 of 1994: the twelve fixed and Easter days, the Monday after any holiday that falls on a Sunday, and the days declared under section 2A (elections, the Rugby World Cup, and 27 December in years when Christmas fell on a Sunday). Each declared day is listed with its source, and declared days have been checked for 2009–2026.

      Checked, not trusted

      The SQL works out working days from a calendar table with a running index. For every one of the closed requests, its answer is compared with the JavaScript library, and the tests fail if the two ever disagree.

      Planted, then found

      The generator planted one change: from 1 July 2025, refunds need a second sign-off. The holiday effect was not planted; it comes from the calendar alone. The tests check that the analysis still finds the first and that no other category moved.

      Run it yourself: npm test, then npm run build. Node 22.13 or later; nothing else to install.
