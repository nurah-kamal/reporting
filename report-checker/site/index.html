How it decides

Worked out again, not compared by eye

Each figure is recalculated from the source rows using the rules under "How each figure is worked out": which columns pair a report row with source rows, which rows are left out, and whether the figure counts rows, adds a column, averages it or takes a share. The report's figure and the source's are compared at the precision the report shows, so 80.6% agrees with 80.64 but not with 80.66.

A cause is named only when it reproduces the number

For a figure that disagrees, the checker changes the source rows in one specific way at a time and recalculates. It names a cause only when that change gives the report's figure exactly. When nothing does, it says so rather than guessing.

The order it tries

  1. Duplicate rows: a row whose reference already appeared, counted again.
  2. Different filter: rows the rule leaves out were kept in.
  3. Stale extract: the newest period matches the source up to an earlier date.
  4. Different date range: a month cut a day or more short or long, or grouped by another date column.
  5. Rounding: within one step of the shown precision, but cut off or rounded twice.
  6. Different filter: one category of rows was left out.
  7. Rows lost in a join: rows with a blank value were dropped.

Totals are checked against the rows above them first. A total that adds up but disagrees with the source carries their mistakes; one whose rows don't cover every source row has lost some, often to an inner join.

What it can't tell

A cause it names is the simplest change that reproduces the figure, not proof of what happened. Two mistakes in one figure, a report laid out with groups across the columns, or a figure made with a calculation it doesn't offer will show as "no single cause found". Those are the ones to check by hand.

The checks are tested against the samples: every planted mistake must be found for the reason it was planted, and every clean figure must pass. Run them yourself with npm test. Node 22.13 or later; nothing to install.
